# Auditing

Use a separate audit pass after implementation/verification. Read the changed files and test changes. Compare every criterion to meaningful assertions or reviewed document evidence. Verify discovery, actual counts, command exits, source hashes and report timestamps. Check negative paths and real-versus-mocked boundaries. Resolve blocking discrepancies before checkpoint.

At phase end, reconcile every step record and ordered commit with actual remote history. Check all requirement ownership, integrated scenarios, outstanding defects and user approvals. A locally authored completion flag cannot prove a successful command or user acceptance. Keep full command output private and publish concise references.

Document audits check completeness, contradictions, links, scope, evidence fidelity and unknowns. Design audits inspect actual returned images at agreed window sizes, text hierarchy, state coverage, keyboard specifications, motion/audio coordination and review feedback. Image prompts and contrast arithmetic are preparatory evidence; they do not prove the images or app are accessible.

Checkpoint source identity uses the tested file manifest/staged tree, then associates the resulting commit and remote receipt. If any tested file changes, rerun affected checks. Detailed evidence is excluded from Git; preserve local reports for handoff. Failed gates are retained, never edited into passes.
