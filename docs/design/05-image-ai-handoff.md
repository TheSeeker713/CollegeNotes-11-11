# CollegeNotes{11:11} — brief for the image-generation AI

Your assignment is to generate reviewable UI/UX images, not write application code. The product owner will compare designs before deciding what to build. Phase 3 implementation/dependency installation is not authorized. No design has been selected yet.

CollegeNotes is a local, browser-first learning workspace for advanced college coursework and ADHD/neurodivergent access. It starts with COMM 110 Presentational Skills and supports courses throughout the owner's education. Meaningful interaction occurs on an ordinary monitor: primarily 2D, selective 2.5D hierarchy, and occasional subject-specific 3D aids. No VR, AR, virtual campus, navigable world, ocean or decorative simulation.

The app must accept repeated screenshots, PDF, DOCX, DRM-free EPUB, pasted text and notes. It preserves originals, supports extraction correction, links explanations/activities to sources, saves progress, provides natural narration and listening, supports prepared offline work and backups. The owner will import real course content after the app exists; no historical screenshots are needed for these mockups. Never request private coursework merely to design the screens.

COMM 110 prohibits AI-generated outlines and assignment sources/citations. Show practice tools that preserve the learner's own writing. Do not add an “AI outline” or “Generate citations” feature. A “View original” study source link is allowed and is different from an assignment citation generator.

Use the supplied synthetic text and exact short UI labels. Do not invent dates, grades, classmates, actual source documents, clinical claims or account capabilities. “Ready offline” means prepared source/activity/audio, never fresh ChatGPT inference. Show sources, learner notes and tutor explanation as different categories.

First round: use 06-round-one-prompts.md to generate three separate images of the same reader: A Quiet Desk, B Focus Studio, C Editorial Notebook. Each image is 1440×900 (8:5 aspect), front-on app canvas, no laptop/device frame, browser address bar, photography or perspective. Save/report each as a distinct image. Do not merge into a contact sheet that makes text unreadable. Pause for the owner's choice before expanding a direction.

If the generator cannot make the exact pixel dimensions, keep the requested aspect ratio and record actual dimensions; do not claim the target size was achieved. Keep all essential content inside a 32px safe margin. Use consistent sharp typography and readable labels. If precise text rendering fails, flag it for correction; an illegible label is not an approved design detail.

After the owner selects a direction, use 07-screen-image-prompts.md to produce the screen family with that direction as the visual reference. Generate one image per requested screen/state, keeping navigation, course name, hierarchy, button language and token roles consistent. Keep actual image files for return; image prompts or verbal descriptions cannot substitute for them.

Required return information for every image: image ID, direction, prompt revision, image file, actual dimensions, generation date/tool if available, and any text/layout deviations. Return the chosen reference alongside later images. Do not assert accessibility compliance or functional behavior from a static image. These are concept mockups; no imports, account calls, audio or persistence actually ran.

The owner then supplies the images for visual inspection and review. We compare them with the screen/state requirements, revise defects, and finish the Phase 2 audit/manual review. Phase 2 remains incomplete until that happens. No image-generation service purchase or credentials are part of this brief.
