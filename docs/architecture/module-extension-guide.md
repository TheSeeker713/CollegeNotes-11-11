# Extending course modules

CollegeNotes keeps course content inside user-created courses. A module descriptor describes an optional capability; it never supplies course material or executable code. The production list in `packages/domain/src/modules.ts` is the trusted, reviewed application registry. An owner-approved future module can be added there with a new ID, label and description. Existing courses remain unchanged until the user enables it; the `course_modules` row is scoped by course ID and records the module schema version.

For a candidate module, use `ModuleRegistry.register` with a data-only descriptor (`id`, `label`, `description`, `schemaVersion: 1`, `capabilities`). The allowed capability names are `sourceTemplates` and `localNotes`. Duplicate IDs, unsupported versions, unknown capability names and extra fields, including callbacks, are rejected. `setRegisteredCourseModule` and `registeredModuleEnabled` exercise the candidate against a synthetic course without changing the production module list or unrelated courses. The fixture in `tests/integration/phase13-module-extension.test.ts` registers a second-course case-note descriptor, toggles it, reopens the database, and verifies its private data and backup survive.

To ship a real business or other subject module later, obtain owner scope approval, add its descriptor to the production registry and give it course-neutral templates. Add versioned storage migration only when its data shape changes; do not overwrite previous rows or writing. Course reads and search must always filter by course ID and approved source revisions. An unsupported stored module version must fail visibly until a tested migration exists. User-imported documents and web text remain data and cannot register modules, invoke callbacks or gain process access.

Backups preserve every stored module row, including an unrecognized data-only descriptor. Unknown modules remain inactive in the current UI and can become available after a trusted application update. External models and credentials remain separate from module data.
